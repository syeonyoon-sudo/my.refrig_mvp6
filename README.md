# 냉장고 한 끼 (Fridge One Meal)

> **로그인 없이 사용하는 버전이에요.** 사이트를 열면 가입·로그인 없이 바로 시작하고, 데이터는 그 브라우저(localStorage)에 저장돼요.
> - 같은 브라우저에서는 새로고침·재접속해도 그대로 남아요. 다른 기기·다른 브라우저와는 공유되지 않아요.
> - 브라우저의 사이트 데이터를 지우면 함께 지워져요. 마이페이지 → "내 데이터 내려받기"로 백업할 수 있어요.
> - Supabase 연결 코드와 DB 구조(`supabase/schema.sql`)는 그대로 남겨 두었어요. 다시 회원가입·로그인을 쓰려면 Vercel 환경 변수에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`와 함께 **`VITE_ENABLE_LOGIN=true`**를 넣고 Redeploy하세요.

자취 대학생·1인 가구를 위한 식재료 관리 + AI 메뉴 추천 + 다회차 식단 + 장보기 웹서비스입니다.

**이 서비스는 두 가지 외부 서비스에 연결해야 모든 기능이 작동해요.**

| 연결할 서비스 | 하는 일 | 환경 변수 |
|---|---|---|
| **Supabase** (무료) | 회원가입·로그인, 계정별 데이터 저장(다른 기기에서도 유지) | `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` |
| **Anthropic Claude API** (유료, 사용한 만큼) | 냉장고 사진 인식, 영수증 글자 인식(OCR), AI 메뉴 추천, AI 추가 질문, 대체 재료 질문 | `ANTHROPIC_API_KEY` |

- 고정된 예시 결과나 "브라우저에만 저장"하는 테스트 모드는 **없어요.**
- 연결이 안 돼 있으면 해당 화면에 무엇을 설정해야 하는지 안내가 나와요.


## 0. 사용자 테스트 반영 개선 (최종 MVP)

사용자 테스트 2회(각 11명) 결과를 반영해 기존 기능은 그대로 두고 아래를 개선했어요. DB 구조(`user_data` 테이블 1개, JSON 저장)와 환경 변수는 바꾸지 않았어요. 새 값은 기존 데이터에 없어도 기본값으로 채워져요.

| 개선 방향 | 바뀐 점 |
|---|---|
| ① 재료 등록 간소화 | **빠르게 추가**: 자주 쓰는 재료를 체크해서 한 번에 등록(내 구매·사용 기록이 많은 재료가 먼저), 한 줄 입력("두부, 대파 2, 돼지고기 300g"), 기한을 "보관 기간으로 추정" 또는 "나중에 입력" 중 선택(추정이면 "기한 추정" 표시) · 직접 등록 폼은 이름·수량·기한·보관만 보이고 나머지는 접힘, 기한 빠른 버튼(오늘·3일·1주·2주·날짜 모름) |
| ② 추천 개인화·다양성 | 보유 재료 일치율(%) 표시 · 같은 종류(밥/국·찌개/면/반찬)·같은 대표 재료가 겹치지 않게 선택 · 최근 3일 안에 만든 메뉴는 뒤로 · **좋아하는 음식·재료** 설정 추가 · "초보 추천"(초보 난이도+20분 이내) 표시 · 추가 구매 없는 메뉴가 먼저 |
| ③ 임박 재료 소진 | 홈 첫 화면에 **먼저 써야 할 재료**와 재료별 "메뉴 N개" 바로가기(그 재료를 쓰는 메뉴만 추천) · **버리지 않고 다 쓰는 순서**(임박 재료를 최대 3끼로 소진하는 메뉴 조합, 못 쓰는 재료는 보관 팁) · 남은 양(처음 넣은 양 대비 %) 표시 · 브라우저 알림 선택(앱을 연 날 하루 한 번) |
| ④ 식단·장보기 | 부족한 재료를 냉장고의 다른 재료로 바꿀 수 있으면 카드에 안내(등록된 대체 규칙만, 알레르기 제외) → 누르면 대체가 적용된 레시피로 이동 · 장보기가 필요한 레시피에 **장보기 없이 만들 수 있는 다른 메뉴** 3개 |
| ⑤ 차별성 | 홈 순서: 임박 재료 → 다 쓰는 순서 → 지금 만들 수 있는 메뉴 → 식단·살린 재료·장보기 요약. 중복되던 홈 알림 목록은 상단 종 알림으로 합침 |

새로 추가된 파일: `src/lib/quickadd.ts`, `src/lib/rescue.ts`, `src/components/QuickAdd.tsx`, `tests/improvements.test.ts` (자동 테스트 17개 추가, 총 47개)

## 1. 기능 목록

### ✅ 구현 완료 (코드로 실제 동작)

**냉장고 사진 인식** (AI 키 필요)
- 사진 촬영(휴대폰 카메라)·업로드 → 서버에서 Claude 이미지 분석 API 호출
- 결과: 식재료명, 종류, 예상 수량, 예상 용량·중량, 포장 특징, 사진 속 위치(번호 표시)
- **미확인 식재료:** AI가 확실히 모르면 이름을 정하지 않고 "미확인"으로 표시해요. 아래 방법으로 해결할 수 있어요.
  - "이 식재료를 인식하지 못했어요. 무엇인가요?" 안내와 함께 직접 입력하거나 검색
  - AI가 제안한 후보 중에서 고르기
  - **AI 재분석:** 그 부분만 잘라서 다시 분석
  - **사진에서 영역 선택해 재분석:** 손가락·마우스로 네모를 그리면 그 부분만 분석
  - 놓친 재료도 영역을 골라 새로 추가할 수 있어요.
- **AI 추가 질문 (대화형):**
  - "이거 용량이 얼마인가요?", "3번은 몇 g이에요?", "두 번째 식재료가 뭔가요?" 같은 질문에 사진을 다시 보고 답해요.
  - 수정안은 **AI 추정**으로 표시되고, "이 값으로 적용"을 눌러야 반영돼요.
- **용량 직접 수정:**
  - 숫자 입력, +/− 버튼, 단위 선택(g·kg·ml·L·개·봉·팩 등)
  - "정확한 용량을 모르겠어요" 선택, 대략값 고르기(가득·¾·절반·¼·조금)
  - AI 추정 / 직접 입력 / 대략 값이 구분돼서 저장되고, 냉장고 목록에도 그대로 표시돼요.
- 유통기한은 사진으로 추정하지 않아요. 비워 두고 사용자가 포장지를 보고 입력해요.
- 확인한 항목만 냉장고에 등록돼요. 같은 재료·같은 기한이면 수량이 합쳐져요.

**영수증 OCR** (AI 키 필요)
- 촬영·업로드 → 상품명·수량·가격·구매일·식재료 여부를 표로 보여줘요.
- 읽지 못한 상품은 **"상품명 미확인 — 이 상품은 무엇인가요?"**로 표시돼요. 직접 입력할 수 있어요.
- 상품별로 수량·단위·가격·보관 장소를 고칠 수 있고, 식재료가 아닌 상품은 빼고 등록할 수 있어요.
- **다시 OCR 실행**(전체), **영역 골라 다시 읽기**(빠진 줄만)
- 구매일은 영수증에서 읽고, 못 읽으면 오늘 날짜로 넣고 그렇다고 알려줘요.
- 유통기한은 만들어 내지 않아요.
- 등록하면 재고 반영 + 구매 내역(실제 금액) + 영수증 기록이 저장돼요.

**AI 메뉴 추천** (AI 키 필요)
- AI가 보는 정보:
  - 실제 재고(수량·유통기한, 양이 "대략"인 재료는 표시)
  - 요리 실력, 좋아하는 맛·싫어하는 재료, 알레르기, 조리 시간, 조리도구, 하루 예산
- 결과: 메뉴명, 재료별 사용량, 보유 재료/부족 재료 구분, 조리 순서, 조리 시간, 예상 비용, **남은 재료 활용법**
- AI 결과는 **같은 규칙으로 다시 검사**해요. 알레르기·조리 시간·도구·기한 지난 재료를 어기면 빼요. 없는 재료를 있다고 가정하지 않아요.
- 내장 레시피 47개를 지금 재고로 계산한 추천도 함께 보여줘요. 이건 AI 키 없이도 작동해요.

**대체 재료·재료 빼기**
- 등록된 대체 규칙: 맛·조리법이 어떻게 달라지는지, 보유 여부, 알레르기 재료 제외
- **AI에게 질문** (AI 키 필요): "두부가 없는데 대체할 수 있나요?", "이 재료를 빼도 되나요?"
  - AI가 제안한 대체재를 사용량과 함께 적용하거나, 재료를 빼고 만들 수 있어요.
  - 알레르기 재료는 대체재로 쓸 수 없게 막아요.

**재고·식단·장보기** (Supabase만 있으면 작동)
- 냉장고 재고
  - 등록·수정·삭제, 수량·용량 수정, 유통기한, 보관 장소
  - 검색, 분류, 임박순 정렬, 기한 경과·재고 부족 표시
- 다회차 식단·냉장고 비우기(오늘/3일/7일)·예산 식단
  - 끼니마다 그 시점의 남은 재고로 계산해서, 같은 재료를 여러 끼니에 나눠도 보유량을 넘지 않아요.
  - 예: 닭가슴살 300g → 오늘 저녁 100g → 내일 점심 100g → 모레 저녁 100g
  - "먹었어요"를 누르면 재고 차감, 취소하면 정확히 복구돼요.
  - 계획을 바꾸거나 취소하면 장보기 목록도 다시 계산돼요.
  - 계획이 끝난 뒤 남는 재료와 계획 기간 중 기한이 지나는 재료를 표시해요.
- 자동 장보기 목록
  - 필요량·현재 보유량·부족량·구매 수량·예상 가격, 구매 완료 체크
  - 구매 완료 → 유통기한·실제 금액 입력 → 재고에 반영
- 외부 쇼핑몰: 쿠팡·컬리·이마트몰·네이버쇼핑의 **상품명 검색 결과**로 이동, 구매 목록 복사
  - 임의의 상품 링크나 상품 가격은 만들지 않아요.
- 회원가입·로그인·로그아웃·비밀번호 변경·비밀번호 재설정 메일
- 계정별 데이터 분리(DB 보안 규칙)
- 재고·추천 기록·장보기·취향·알레르기 저장, 다른 기기에서 로그인해도 유지
- 다른 기기에서 바꾼 내용은 이 화면으로 돌아오면 다시 불러와요.

## 2. GitHub에 올리기 (⚠️ 폴더째 올리기)

지난번 오류의 원인은 **폴더(`src`, `api` 등)가 빠지고 파일만 올라간 것**이었어요.

1. `fridge-one-meal.zip` **압축을 풀어요.**
2. GitHub에서 **New repository**를 누르고 새 저장소를 만들어요(예: `fridge-one-meal`). 예전 저장소에 덮어쓰지 마세요.
3. **uploading an existing file**을 눌러요.
4. 파일 탐색기에서 압축을 푼 `fridge-one-meal` 폴더 **안으로** 들어가요. `Ctrl + A`로 폴더·파일을 전부 선택해요.
5. 선택한 것을 **크롬의 업로드 화면으로 끌어다 놓아요.**
   - **"choose your files" 버튼은 쓰지 마세요.** 이 버튼으로는 폴더가 선택되지 않아요.
6. 올라가는 목록에 `src/App.tsx`처럼 폴더 경로가 붙어 있으면 맞게 된 거예요. 확인했으면 **Commit changes**를 눌러요.
7. 저장소 첫 화면에 아래가 보여야 해요.
   - 폴더: `api`, `public`, `src`, `supabase`, `tests`
   - 파일: `package.json`, `vercel.json`, `index.html` 등

> 실제 키가 들어간 `.env` 파일은 절대 올리지 마세요.

## 3. Vercel로 배포하기

1. vercel.com에서 **Continue with GitHub**로 로그인해요.
2. **Add New… → Project**에서 새 저장소를 **Import**해요.
3. **Project Name**은 영어 소문자·숫자·하이픈만 써요 (예: `fridge-one-meal`).
4. Framework Preset이 **Vite**로 자동 선택되는지 확인해요. Build·Output 설정은 그대로 두면 돼요.
5. **Environment Variables**에 6장의 값 3개를 넣어요. 4장·5장에서 발급받은 값이에요.
6. **Deploy**를 누르면 1~2분 뒤 주소가 생겨요.

빌드 로그에 `> fridge-one-meal@1.0.0 build`가 보이면 이 버전이 맞게 빌드되는 거예요.

> 환경 변수를 나중에 넣거나 바꿨다면 **Deployments → 최신 배포 ⋯ → Redeploy**를 꼭 눌러요.

## 4. Supabase 연결 (회원가입·DB)

1. supabase.com에 GitHub로 로그인하고 **New project**를 만들어요.
   - 데이터베이스 비밀번호는 따로 적어 두세요.
   - Region은 **Northeast Asia (Seoul)**을 추천해요.
2. 왼쪽 **SQL Editor → New query**에 `supabase/schema.sql` 내용을 전부 붙여 넣고 **Run**을 눌러요.
   - "Success"가 나오면 사용자별 데이터 테이블과 **본인 데이터만 읽고 쓰는 보안 규칙(RLS)**이 만들어진 거예요.
3. **Project Settings → API**(또는 API Keys)에서 두 값을 복사해요.
   - **Project URL** → `VITE_SUPABASE_URL`
   - **anon public**(또는 publishable) 키 → `VITE_SUPABASE_ANON_KEY`
   - ⚠️ `service_role`/secret 키는 절대 쓰지 마세요.
4. **Authentication → URL Configuration**을 설정해요.
   - Site URL: Vercel 주소 (예: `https://fridge-one-meal.vercel.app`)
   - Redirect URLs에 두 개 추가: `https://(내 주소)/login`, `https://(내 주소)/reset-password`
5. Vercel 환경 변수에 3번의 두 값을 넣고 **Redeploy**해요.
6. (선택) 발표 시연을 쉽게 하려면 **Authentication → Sign In / Providers → Email → Confirm email**을 꺼요. 가입하자마자 바로 로그인돼요. 켜 두면 인증 메일 링크를 눌러야 로그인돼요.

## 5. AI 연결 (사진·영수증·추천)

1. console.anthropic.com에 가입하고 **Billing**에서 결제 수단·크레딧을 등록해요.
2. **API Keys → Create Key**로 키(`sk-ant-...`)를 만들어 복사해요. 키는 한 번만 보여요.
3. Vercel 환경 변수에 `ANTHROPIC_API_KEY`로 넣어요.
   - **이름 앞에 `VITE_`를 붙이면 안 돼요.** 붙이면 브라우저에 키가 노출돼요.
4. **Redeploy**하면 사이트 위쪽 배지가 **"AI 연결됨"**으로 바뀌어요.

비용과 시간:
- 사진·영수증 1장 분석이나 질문 1번에 보통 10~40초 걸리고, 한 번에 수십 원 정도 나와요(모델·이미지 크기에 따라 달라요).
- Console의 **Limits**에서 월 사용 한도를 정해 두세요.
- 모델은 `ANTHROPIC_MODEL`로 바꿀 수 있어요. 비우면 `claude-sonnet-5-5`를 써요.

API 키는 서버 함수(`api/ai.ts`)에서만 읽어요. 브라우저 코드에는 들어가지 않아요.

## 7. 배포 후 확인 순서 (발표 전 한 번씩)

1. **가입:** 회원가입 → 로그인 → 대시보드가 보이는지 확인해요.
2. **사진 인식:** 냉장고 → 사진으로 등록에서 실제 냉장고 사진을 올리고 "AI로 재료 찾기"를 눌러요.
   - 미확인 재료가 있으면 후보 선택 / AI 재분석 / 영역 선택을 해 봐요.
   - "AI에게 추가로 물어보기"에서 "1번 용량이 얼마인가요?"를 물어보고 결과를 적용해요.
   - 등록한 뒤 냉장고 목록에 들어갔는지 확인해요.
3. **영수증:** 실제 영수증을 찍어 표를 확인하고, 미확인 상품을 입력해서 등록해요.
4. **AI 추천:** 메뉴 추천에서 "AI에게 새 메뉴 받기" → 레시피 → "요리 완료"를 눌러 재고가 줄었는지 확인해요.
5. **식단·장보기:** 식단 만들기 → 장보기 목록 자동 생성 → 장바구니 → 쇼핑몰 검색 이동 → 구매 완료 → 재고 반영까지 이어서 해 봐요.
6. **다른 기기:** 휴대폰으로 같은 계정에 로그인해서 같은 데이터가 보이는지 확인해요.

오류가 나면 화면의 빨간 메시지를 확인하세요. 서버 쪽 오류는 Vercel → 프로젝트 → **Logs**에서 볼 수 있어요.

## 8. 배포할 때 주의사항

- **키 관리:** 키를 GitHub 파일에 적지 마세요. 실수로 올렸다면 바로 해당 서비스에서 키를 삭제하고 새로 발급하세요.
- **AI 결과는 추정이에요:**
  - 사진 속 용량·개수는 화면에 "AI 추정"으로 표시돼요.
  - 알레르기는 등록된 재료 정보와 키워드로 걸러요. 가공식품은 실제 포장의 성분 표시를 확인하도록 안내해 주세요.
- **사진 크기:** 브라우저에서 1280~1600px로 줄여서 보내요. Vercel의 요청 크기 제한(4.5MB) 안에 들어가요.
- **함수 실행 시간:** 새 Vercel 프로젝트는 서버 함수가 최대 300초까지 실행돼요(Fluid compute 기본값). 아주 예전에 만든 프로젝트라 10초에서 끊기면 Settings → Functions에서 **Fluid Compute를 켜세요.**
- **Supabase 무료 프로젝트:** 오래 접속이 없으면 일시정지될 수 있어요. 발표 전에 대시보드에서 상태를 확인하세요.

## 9. 이전 배포 오류 해결 내용

- **`[unused_function] The pattern "api/*.ts"`:** `vercel.json`의 `functions` 설정이 실제 파일 위치와 맞지 않을 때 나는 오류예요.
  - 이 프로젝트는 `functions` 설정을 쓰지 않아요. 루트의 `api/ai.ts`, `api/status.ts`를 Vercel이 자동으로 인식해요.
- **`TS18003: No inputs were found` / `fridge-meal@1.0.0`:** 예전 프로젝트 파일을 올렸고, `src` 폴더가 빠진 경우예요. 2장대로 폴더째 올리면 해결돼요.

```bash
# Node.js 18 이상
npm install
cp .env.example .env.local      # 값 채우기
```

- 계란 2개(D-1) + 10개(D-20)에서 3개 사용 → 기한 임박 2개 먼저 쓰고, 나머지 1개는 새 묶음에서 → 9개 남음
- "먹었어요"를 취소하면 차감했던 묶음에 그대로 되돌려요.
